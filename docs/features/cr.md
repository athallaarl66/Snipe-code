# CR: SNIPE-CODE sebagai platform scaffolding, kualitas kode, dan QA terpadu

Status: usulan arah produk; belum disetujui dan baru sebagian kecil diimplementasikan. Jenis bukti: peninjauan statis source + test yang ada, bukan audit keamanan menyeluruh, bukan exploit, bukan eksekusi CI/Docker, bukan validasi visual PDF. Produk tetap **SNIPE-CODE**, CLI-only dengan integrasi agent melalui skill dan MCP opsional; tanpa GUI atau Tauri. Tidak ada produk atau brand aplikasi QA terpisah.

Snapshot: commit `0c0ea4f` + working tree yang belum di-commit (perubahan user pada `openspec/changes/harden-verify-safety/tasks.md`, `src/verify/mod.rs`, `tests/verify_test.rs`). Semua `path:line` merujuk snapshot tersebut, bukan index XERJ (index terbukti stale terhadap kode sekarang). Bila source berubah, klaim di sini harus diverifikasi ulang.

## 1. Kebutuhan, tujuan, dan batas janji

Pertahankan `new` beserta template, wizard, override, dry-run, dan perilaku publiknya. Tambahkan alur tunggal: pilih proyek → inspeksi statis/security/SCA → evaluasi quality gate dan perubahan relatif baseline/PR → rancang test case positif/negatif dan script yang dapat ditinjau → jalankan di lingkungan terisolasi bila disetujui → tinjau laporan, riwayat, dan saran fix. Hasil harus bisa diakses dari CLI dan agent dengan model data serta kebijakan izin sama. Pengguna: developer individu offline, reviewer PR, QA, dan tim yang memakai konektor kerja. Keberhasilan berarti bukti cakupan, status tidak diketahui, dan side effect terlihat jelas; bukan janji akurasi atau cakupan setara semua edisi SonarQube dalam satu rilis. Profil bahasa/framework, aturan, metrik, dan ketepatan dibuat eksplisit per milestone.

**Prinsip kontrak:** analisis statis default tidak menjalankan kode target; export hanya menulis ke tujuan yang disetujui; instalasi, eksekusi test, akses endpoint, pengiriman atau pembagian data, update advisory, sinkronisasi konektor, dan perubahan source memerlukan preview serta approval eksplisit terpisah sebelum aksi. Temuan kandidat RCE/command injection, SQLi, XSS, dan secrets bukan bukti eksploitasi. Tidak ada perbaikan otomatis atau eksekusi test atas proyek tak dikenal secara default.

## 3. Usulan arsitektur dan kontrak data

Keputusan **usulan, belum implemented** untuk bagian yang belum ada: ekstrak core Rust yang dipakai CLI; agent memakai kontrak CLI/JSON atau adapter MCP terkontrol dengan kebijakan core yang sama. Tanpa desktop GUI, Tauri, atau runtime web service lokal. Scaffolding existing tetap core. Status per konsep: `scan` (read-only, sudah ada), `export` (tulis hanya path terpilih, sudah ada), `history` (SQLite lokal, sudah ada), `gate` (belum ada), `qa plan` / `qa run` (belum ada), `connector` (belum ada). Nama final subcommand QA/gate masih rancangan, bukan perintah yang tersedia.

Model hasil berversi: `project_id`, `run_id`, timestamp, repo/commit/ref opsional, config hash, target scope, daftar file dianalisis/dikecualikan, engine/rule pack version, advisory snapshot time, environment mode, per-rule `evaluated`/`not-applicable`/`unknown`/`error`, temuan `rule_id`, fingerprint, severity, confidence, bukti lokasi/trace, status triage, saran fix dan caveat. ## 4. Lingkup mesin kualitas dan QA (target, bertahap)

### 4.1 Scanner dan pelaporan

- SAST: mulai rule spesifik bahasa/framework dan analisis source-to-sink **terbatas dengan dukungan eksplisit**, misalnya input tak tepercaya → proses shell/API execution, query dinamis, atau HTML sink. Trace hanya jika ada bukti; sanitization/parameterisasi dinilai dalam konteks. Heuristik sekarang (`src/audit.rs:314-620`) tetap diberi label legacy, diuji regresi/false positive, dan tidak dicampur rule baru tanpa versi.
- SCA: parsing manifest/lockfile serta direct/transitive graph per ekosistem; advisory cache/snapshot offline dengan `fetched_at` UTC; hasil tanpa snapshot atau stale = `unknown`, bukan nol vuln. Jangan menjalankan tool yang mengunduh sebagai mode offline. Jalur `npm audit`/`composer audit`/`dotnet --vulnerable` sekarang (`src/verify/detect.rs:114-183`) belum memenuhi ini.
- Quality: maintainability, duplication, coverage import (tidak dihitung dari scan statis), quality gate berversi, baseline/history, PR delta dengan rename matching dan `unknown` untuk konflik/missing base. Gate memisahkan `pass`/`fail`/`unknown`/`not-applicable`; fail-closed pada unknown boleh sebagai kebijakan, tidak boleh diam-diam pass.
- Laporan memuat scope, rule yang berjalan, keterbatasan, advisory timestamp, provenance coverage, rincian delta, bukti, prioritas, dan saran fix sebagai **usulan** yang wajib review. PDF panjang wajib memuat seluruh temuan tanpa terpotong, dibuktikan dengan ekstraksi teks + inspeksi render, bukan dari adanya file.

### 4.2 QA test case, script, runner

- Rencanakan test case positif/negatif, boundary, auth/permission, validation/error, regresi; tautkan requirement → case → script → hasil. Adapter bertahap: Postman CLI untuk proyek pengguna, lalu Playwright, Bruno, Maestro, unit/regression sesuai prioritas. Static syntax/struktur script diverifikasi sebelum status `ready`; generated script bukan bukti lulus.
- Setup Postman CLI: deteksi instalasi/konfigurasi, tampilkan rencana, versi, sumber, file tujuan, collection, environment, endpoint, dan data; instalasi/perubahan konfigurasi hanya setelah approval eksplisit; tanpa credential plaintext. Tool hilang atau approval ditolak → `unavailable`/`blocked`, bukan lulus.
- `qa plan` read-only; `qa run` memerlukan daftar command, cwd, endpoint, environment, mount, network, dan artefak tulis yang disetujui, lalu menangkap exit, log tersanitasi, evidence, timeout, status skipped/unavailable, dan bisa dibatalkan.
- DB aman: default tidak menjalankan test pada env belum dipercaya. Preflight sekarang mengklasifikasi target (allowlist host, tolak produksi/ambigu; `src/verify/mod.rs:423-556`) tetapi **belum membuktikan isolasi**. Sebelum runner QA wajib: instance disposable dengan identitas unik, kredensial terbatas, network deny-by-default, fixture/reset/cleanup dalam boundary terverifikasi. Jika isolasi tidak terbukti → fail closed. Jalur non-DB juga butuh batas filesystem/proses/network/secret; runner harus menyatakan tingkat isolasi aktual atau menolak.

### 4.3 Offline, AI, agent, konektor

- Mode offline dasar: scan rule lokal, SCA snapshot lokal, laporan dan riwayat tanpa egress; tidak bergantung model. Local AI opsional dengan input/akses dibatasi, menampilkan model/izin/provenance. Online AI opt-in per proyek/permintaan: preview/redaksi payload, provider, kategori data, retention, consent; default tidak mengirim source/secret/log/findings. Jawaban AI = saran, bukan bukti.
- Agent skill = dokumen petunjuk; slash command = entry eksplisit pengguna; keduanya bukan runtime SNIPE-CODE dan tanpa izin implisit. `templates/ai-tools/content/command.md:1-10` wajib direvisi menjadi preview + konfirmasi + pelaporan verifikasi sebelum artifact ini dipromosikan. Permission check di Rust core, bukan hanya prompt.
- Konektor MCP Figma/Figcraft/Taiga/Jira/Slack = adapter opsional per layanan, default read-only/disabled, dengan preview payload, approval per aksi, idempotency, audit trail, rate limit, dan scrub prompt injection. Data proyek tidak dikirim hanya karena konektor dikonfigurasi.

## 7. Kompatibilitas `audit` dan migrasi

`audit` existing berarti **scan + export** ke `Audit_Report.*` dalam proyek yang dipindai (`src/audit.rs:170-210`), termasuk saat `--json`; jangan ubah diam-diam menjadi read-only atau menghapus nama file/format/exit behavior. Jalur baru (`scan`/`export`) sudah memisahkan read-only dan tulis eksplisit; `audit` legacy tetap dengan notice side effect di stderr (`src/main.rs:324`). Bila `audit` didepresiasi: warning + versi/tanggal + panduan pengganti + test kompatibilitas. Jangan menerjemahkan exit `0` lama menjadi bukti semua gate SCA/SAST baru lulus. `new`, `analyze`, `verify`, dan artifact agent lama punya fixture regresi; perubahan perilaku `verify` (approval wajib, exit 4) harus diumumkan sebagai perubahan yang disengaja, bukan bypass tersembunyi. Riwayat lama tanpa fingerprint diberi `legacy/unmapped` dan tidak dicocokkan seolah hasil baru (`src/history.rs:570-635`).

## 8. Di luar lingkup dan keamanan destruktif

Di luar CR: GUI/desktop/Tauri, membangun clone semua edition/aturan SonarQube sekaligus, klaim menemukan semua vulnerability, penilaian exploit otomatis, deployment/cloud service, telemetry default, auto-fix tanpa review, auto-install toolchain, menjalankan target tak dikenal, membuka DB produksi, overwrite/hapus proyek untuk cleanup, atau mengirim data ke AI/konektor tanpa persetujuan. QA tetap dalam CLI SNIPE-CODE dan integrasi agent. Semua operasi destruktif butuh target eksplisit, preview, batas path/DB yang dapat dibuktikan, dan approval baru; kegagalan preflight harus berhenti sebelum side effect.
