# CR: SNIPE-CODE sebagai platform scaffolding, kualitas kode, dan QA terpadu

Status: usulan arah produk; belum disetujui atau diimplementasikan. Jenis bukti: peninjauan statis source dan dokumen, bukan audit keamanan yang dieksekusi, pengujian, atau validasi GUI/PDF. Produk tetap **SNIPE-CODE** dengan tiga surface: CLI, desktop GUI, dan integrasi agent. Tidak ada produk atau brand aplikasi QA terpisah. Semua kemampuan di bawah ialah target bertahap dalam **satu CR**, bukan klaim fitur saat ini.

## 1. Kebutuhan, tujuan, dan batas janji

Pertahankan `new` beserta template, wizard, override, dry-run, dan perilaku publiknya. Tambahkan alur tunggal: pilih proyek → inspeksi statis/security/SCA → evaluasi quality gate dan perubahan relatif baseline/PR → rancang test case positif/negatif dan script yang dapat ditinjau → jalankan di lingkungan terisolasi bila disetujui → tinjau laporan, riwayat, dan saran fix. Hasil harus bisa diakses dari CLI, GUI, dan agent dengan model data serta kebijakan izin sama. Pengguna: developer individu offline, reviewer PR, QA, dan tim yang memakai konektor kerja. Keberhasilan berarti bukti cakupan, status tidak diketahui, dan side effect terlihat jelas; bukan janji akurasi atau cakupan setara semua edisi SonarQube dalam satu rilis. Profil bahasa/framework, aturan, metrik, dan ketepatan dibuat eksplisit per milestone.

**Prinsip kontrak:** analisis statis default tidak menjalankan kode target; export hanya menulis ke tujuan yang disetujui; runner, update advisory, AI online, sinkronisasi konektor, dan perubahan source punya consent tersendiri. Temuan kandidat RCE/command injection, SQLi, XSS, dan secrets bukan bukti eksploitasi. Tidak ada perbaikan otomatis atau eksekusi test atas proyek tak dikenal secara default.

## 3. Usulan arsitektur dan kontrak data

Keputusan **usulan, belum implemented**: ekstrak core Rust yang dapat dipakai CLI dan backend desktop **Tauri + TypeScript**; GUI menampilkan model hasil yang sama, bukan scanner kedua. CLI memanggil core langsung; desktop memakai API command Tauri yang dibatasi izin; agent memakai kontrak CLI/JSON atau adapter terkontrol yang sama. Scaffolding existing tetap core. Tidak mengharuskan runtime web service lokal. Pemisahan konsep: `scan` (read-only, hasil terstruktur), `export` (tulis hanya path yang dipilih), `qa plan` (test case dan script untuk review), `qa run` (isolasi dan consent), `gate` (evaluasi), `history` (SQLite lokal), `connector` (opt-in). Nama subcommand final ditetapkan setelah uji kompatibilitas; nama ini rancangan, bukan perintah yang tersedia.

Model hasil berversi: `project_id`, `run_id`, timestamp, repo/commit/ref opsional, config hash, target scope, daftar file dianalisis/dikecualikan, engine/rule pack version, advisory snapshot time, environment mode, per-rule `evaluated`/`not-applicable`/`unknown`/`error`, temuan `rule_id`, fingerprint berbasis rule+lokasi semantik yang ter-normalisasi, severity, confidence, bukti lokasi/trace, status triage, saran fix dan caveat. Path lokal/secret disamarkan pada export/share; format report Markdown, JSON, PDF, DOCX dan tampilan GUI merepresentasikan hasil kanonik yang sama, lengkap dengan omission/truncation eksplisit. Tak ada angka coverage atau security score untuk cakupan yang tidak dihitung.

## 4. Lingkup mesin kualitas dan QA

### 4.1 Scanner dan pelaporan

- SAST: mulai rule spesifik bahasa/framework dan analisis source-to-sink **terbatas dengan dukungan eksplisit**, misalnya input tak tepercaya → proses shell/API execution, query dinamis, atau HTML sink. Trace hanya jika ada bukti; sanitization/parameterisasi dinilai dalam konteks. RCE/command injection, SQLi, XSS, secrets dilaporkan sebagai **kandidat** dengan confidence dan langkah review manual. Sink yang tidak dimodelkan, dynamic dispatch, bahasa tak didukung, file dikecualikan, dan timeout ialah `unknown`, bukan clean. Heuristik lama tetap diberi label legacy dan diuji untuk regresi/false positive; baseline tidak boleh mencampur rule baru-lama tanpa versi.
- SCA: parsing manifest/lockfile serta direct/transitive graph per ekosistem yang didukung; advisory cache/snapshot offline berisi sumber, versi, dan `fetched_at` UTC; hasil tanpa snapshot atau snapshot kedaluwarsa = `unknown`/stale, bukan nol vuln. Update online hanya setelah opt-in/approval, pencatatan URL/metadata keluar, validasi integritas/sumber dan rollback snapshot gagal. Jangan menjalankan `npm audit` atau tool yang mengunduh sebagai mode offline. Dukungan Go/Java/Cargo tidak boleh dianggap covered sebelum adapter dan fixture lulus.
- Quality: maintainability (rule/code smell, kompleksitas dengan definisi dan ambang terukur), duplication (token/blok minimal terkonfigurasi dan exclusions), coverage (impor report existing dengan format dan provenance; **tidak dihitung dari scan statis**), quality gate (aturan berversi per metrik dan severity), history/baseline (fingerprint stabil, triage dan compare), PR delta (base/head/ref, new/changed/resolved dan rename matching; konflik merge dan missing base `unknown`). Gate default memisahkan `pass`, `fail`, `unknown`, `not-applicable`; kebijakan organisasi boleh memilih fail-closed pada unknown, tak boleh diam-diam mengubahnya menjadi pass. Tak ada claim parity dengan SonarQube editions atau score tunggal yang menyembunyikan unknown.
- Laporan memuat scope, rule yang berjalan, keterbatasan, advisory timestamp, asal coverage, rincian delta, bukti, prioritas, dan saran fix dengan before/after sebagai **usulan** yang wajib review serta test; tidak auto-edit. PDF panjang wajib pagination tanpa kehilangan finding; JSON machine-readable tidak menciptakan report di folder proyek kecuali diminta.

### 4.2 QA test case, script, runner

- Rencanakan test case positif/negatif, boundary, auth/permission, validation/error, dan regresi; tautkan requirement → case → script → hasil. Output script Playwright, Postman collection, Bruno, Maestro, serta unit/regression dengan template syntax yang jelas; hanya generator untuk framework yang terdeteksi/dipilih. Static syntax/struktur script diverifikasi sebelum status `ready`; generated script bukan bukti test lulus.
- `qa plan` read-only terhadap source dan belum menjalankan script; menyimpan/export rancangan butuh tujuan tulis. `qa run` memerlukan daftar command, working directory, endpoint, environment, mount, network, dan artefak tulis yang disetujui. Runner menangkap exit, log tersanitasi, evidence, timeout, status skipped/unavailable, dan dapat membatalkan; tidak mengklaim lolos jika tool hilang. Adapter tidak menginstal tool diam-diam.
- DB aman: default **tidak** menjalankan test atau `verify --only test` terhadap env yang belum dipercaya. Preflight memeriksa konfigurasi target DB dan env/URL secara redacted; blokir host produksi, remote, credential tidak dikenal, atau target ambigu. DB test disposable/terisolasi dengan identitas unik, kredensial terbatas, network deny-by-default, dan allowlist target; fixture/reset/cleanup hanya dalam boundary sandbox yang diverifikasi. Jika tidak bisa membuktikan isolasi, fail closed tanpa menjalankan command (termasuk install/hook yang bisa menulis DB); mode eksplisit legacy berisiko hanya setelah review dan consent terpisah. Jangan mengandalkan nama `test` pada URL sebagai bukti. Jalur non-DB tetap butuh isolasi filesystem, proses, network, dan secret; Windows/macOS/Linux punya kemampuan berbeda, sehingga runner harus menyatakan tingkat isolasi aktual atau menolak eksekusi.

### 4.3 Offline, AI, agent, konektor

- Mode offline dasar: scan rule lokal, SCA snapshot lokal, laporan dan riwayat tanpa egress; tidak bergantung pada model. Local AI opsional: model tersedia lokal dan dibatasi input/akses, tetap dapat mengakses proses/file host bila tidak disandbox; tampilkan model, izin, dan provenance. Online AI **opt-in per proyek/permintaan**: preview/redaksi payload, pilih provider, kategori data, retention, dan consent sebelum outbound; default tidak mengirim source, secret, log, atau findings. Jawaban AI diberi label saran dan tidak menjadi bukti; gagal/offline fallback ke rule deterministik. Credential di OS store, bukan `.env` proyek atau SQLite plaintext.
- Agent skill = dokumen petunjuk yang dimuat agent sesuai relevansi; slash command = entry eksplisit oleh pengguna; keduanya bukan runtime SNIPE-CODE, bukan jaminan dieksekusi, dan tidak punya izin implisit. Pertahankan pola artifact registry lama, tambahkan adapter per host hanya bila host mendukung; Hermes skill tidak dipasarkan sebagai slash command. Instruksi yang meminta fix/test di `templates/ai-tools/content/command.md:1-10` harus direvisi untuk meminta preview, konfirmasi perubahan/eksekusi, dan pelaporan verifikasi. Agent memakai operasi core yang sama dengan CLI/GUI; permission check di core, bukan hanya prompt.
- Konektor MCP Figma, Figcraft, Taiga, Jira, Slack bersifat adapter **opsional** per layanan. Discovery tool/capability, auth scope minimum, dan pemetaan requirement/desain/issue/notifikasi dipisah; tak menjanjikan ketersediaan server atau API tertentu tanpa validasi. Default read-only/disabled; setiap egress, create/update ticket, unggah desain, dan kirim pesan memerlukan preview payload, target, hak akses, approval per aksi, idempotency key, audit trail, rate limit dan penanganan kegagalan. Data proyek tidak diunggah hanya karena connector dikonfigurasi. Host MCP tak dipercaya: batas proses, izin file/network, dan scrub prompt injection dari konten eksternal.

## 6. Urutan dependensi dan milestone satu CR

Setiap milestone hanya diterima bila bukti hasil bisa diulang; **belum ada AC berikut yang dieksekusi oleh CR ini**. Bila target angka akurasi/ambang dipilih kemudian, versioning dan korpus uji disetujui sebelum gate diberlakukan; tidak menjanjikan semua rule/language serentak.

| Tahap | Dependensi dan deliverable | Acceptance criteria terukur, termasuk negatif |
| --- | --- | --- |
| M0 — kontrak keselamatan dan kompatibilitas | Mulai dari parser/report dan risk `verify`; dokumentasi current state, matriks izin/side effect. | Kasus `audit` lama (`--export md/pdf,docx`, `--json`, exit 0/1/2/3) diuji regresi; unknown flag/dua positional ditolak pada interface baru tanpa salah scan; `scan` baru tidak menulis target, `export` hanya tujuan terpilih. `verify --only test` pada DB remote/ambigu diblokir sebelum spawn; unavailable terlihat non-pass meski gate lain lulus. Dokumen tak lagi menyebut `audit` read-only. AC negatif P0: symlink file `.env`/`.env.local` yang menunjuk file di luar root tidak dibaca dan konten target tidak ditulis ke laporan/JSON; verifikasi pula semantik symlink/junction Windows dan tolak traversal keluar root. |

**Gate lintas tahap:** per milestone sertakan fixture, test negatif, versi schema/rule, coverage matriks kemampuan per bahasa/OS/surface, diff kontrak kompatibilitas, dan catatan manual UAT. Bila surface belum ada di tahap awal, parity diberi `not-applicable — not delivered`, bukan lulus. Target performa dan false-positive rate ditetapkan dari corpus representatif dengan ukuran/versi/baseline terdokumentasi; klaim akurasi dilarang sebelum data itu ada.

Urutan P0 mengikuti dependensi jalur kode: tutup pembacaan symlink di batas traversal sebelum memperluas pemindaian; pastikan kontrak `unavailable` benar sebelum menambah gate; isolasi subprocess sebelum runner QA yang lebih luas karena `verify` menjalankan proses di direktori proyek dengan environment terwaris (`src/verify/exec.rs:52-80`). Lihat temuan dan mitigasi terkait di §2 dan §5, tanpa mengulang rincian di sini. `tests/verify_test.rs:307-355` membuktikan status 3 saat tak ada gate berjalan; tambahkan kasus campuran (`unavailable` bersama gate yang berjalan) karena `src/verify/mod.rs:179-191` saat ini dapat memberi exit 0 untuk laporan parsial tanpa failure.

Untuk setiap relasi kode yang dipakai sebagai dasar keputusan, verifikasi edge terhadap source dan test terkait, bukan Graphify saja. Bila Graphify diperlukan untuk keputusan arsitektur yang mencakup dokumentasi, bangun ulang corpus berisi source dan dokumen terkait, lalu catat batas ekstraksi; graph code-only tidak mewakili relasi dokumentasi.

## 7. Kompatibilitas `audit` dan migrasi

`audit` existing berarti **scan + export** ke `Audit_Report.*` dalam proyek yang dipindai (`src/audit.rs:88-125`), termasuk saat `--json`; jangan ubah diam-diam menjadi read-only atau menghapus nama file/format/exit behavior. Jalur baru memisahkan scan read-only dan export eksplisit; bila `audit` legacy didepresiasi, tampilkan warning side effect di stderr, versi dan tanggal deprecation, panduan pengganti, serta test kompatibilitas. Jangan menerjemahkan exit `0` lama menjadi bukti semua gate SCA/SAST baru lulus; representasikan coverage/unknown di payload berversi. Existing `new`, `analyze`, `verify` dan artifact agent lama punya fixture regresi; unsafe `verify` perlu default guard dengan perubahan perilaku yang diumumkan serta jalur migrasi consent eksplisit, bukan bypass tersembunyi. Riwayat laporan lama tanpa fingerprint diberi `legacy/unmapped` dan tidak dicocokkan seolah hasil baru.

## 8. Di luar lingkup dan keamanan destruktif

Di luar CR: membangun clone semua edition/aturan SonarQube sekaligus, klaim menemukan semua vulnerability, penilaian exploit otomatis, deployment/cloud service, telemetry default, auto-fix tanpa review, auto-install toolchain, menjalankan target tak dikenal, membuka DB produksi, overwrite/hapus proyek untuk cleanup, atau mengirim data ke AI/konektor tanpa persetujuan. UI QA tetap di dalam SNIPE-CODE. Semua operasi destruktif butuh target eksplisit, preview, batas path/DB yang dapat dibuktikan, dan approval baru; kegagalan preflight harus berhenti sebelum side effect.

## 9. Rencana verifikasi (belum dijalankan)

1. Review kontrak dan threat model CLI/GUI/agent, outbound AI/MCP, DB runner, dan status gate; petakan setiap AC ke fixture dan pemilik.
2. Jalankan unit/contract test parser, scan/export, rule fixtures positif-negatif, snapshot offline/stale, SQLite migration, baseline/PR delta, tri-state gate, dan backward compatibility pada environment aman; catat command, versi tool, exit, serta artefak, jangan menyimpulkan dari kode saja.
3. Jalankan integrasi QA hanya pada sandbox disposable tanpa credential/DB nyata, dengan DB target palsu produksi/unknown sebagai kasus penolakan; uji batas network/file/permission, timeout, cleanup, dan unavailable.
4. Bandingkan hasil fixture identik di CLI, GUI, dan agent (ID, jumlah, unknown, approvals); inspeksi PDF/DOCX/render dan JSON. Uji konektor lewat mock dahulu, lalu izin nyata dengan persetujuan terpisah.
