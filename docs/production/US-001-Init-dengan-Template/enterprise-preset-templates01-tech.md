# US-001: Init dengan Template — Technical Specifications

> Status: the folder structure below is generated by the current presets. Page
> content, SEO tags, dark mode, and responsive layout are design plans, not generated
> output. See `docs/features/technical.md` section 3 for what a preset actually writes.

## CLI Commands
```bash
snipe-code new                              # interactive mode
snipe-code new --template blog               # skip template prompt
snipe-code new --frontend nextjs --backend none --database none --name demo
```

## Dependencies
- `dialoguer` — interactive prompts
- `serde` + `serde_json` — preset parsing
- `include_dir` — embeds `templates/` into the binary
- `std::fs` — staging directory and publish

## Data Structure
```rust
// templates/presets/<id>/preset.json
struct Preset {
    id: String,
    name: String,
    description: String,
    icon: String,
    structure: PresetStructure,   // folders, files, rules
}
```

## Error Handling
| Error | Message |
|-------|---------|
| Target exists, interactive | Prompt `Overwrite (replace existing)` or `Cancel` |
| Target exists, no terminal | `Error: Folder "<path>" already exists`, exit 1 |
| No stack selected | `Pilih minimal Frontend atau Backend`, exit 2 |
| Unknown template id | `unknown template: <id>`, exit 2, nothing written |
| Unknown option | `Unknown option or positional argument: <arg>`, exit 2 |

## Performance
- Templates are embedded at compile time, so selection and listing need no disk
  reads. Nothing here is benchmarked; the CI gate is correctness, not timing.
- Writing is sequential into a staging directory; no parallel folder creation.
